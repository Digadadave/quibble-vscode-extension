Extension Architecture

📁 File Structure

vscode-code-review/
├── src/
│   ├── extension.ts          ← entry point
│   ├── ReviewPanel.ts        ← WebView panel
│   ├── ReviewTreeProvider.ts ← sidebar tree
│   ├── CommentManager.ts     ← read/write JSON
│   ├── GitService.ts         ← git log / diff
│   └── DiffDecorator.ts      ← inline gutters
├── webview/
│   ├── review.html           ← panel HTML
│   ├── review.css
│   └── review.js             ← panel scripts
└── .code-review/             ← per-repo
    └── reviews.json

⚡ Key Interactions

Git log → parse commits for sidebar
git diff <hash> → render in WebView
Click + icon → open comment compose
Submit comment → write to reviews.json
Agent reads reviews.json at session start
Agent writes thread reply + status update
FileWatcher → extension refreshes on change
Mark addressed → update status in JSON

Agent-Readable Prompt Block

The "Copy agent prompt" button generates this block, which you paste into Claude Code: 

## Code Review — Open Comments to Address

There are 2 open review comments in .code-review/reviews.json.
Please address each one and update the file accordingly.

### [cr_a1b2c3d4] src/extension.ts line 42 — OPEN
> This activate() function should handle the case where context
> is undefined or the workspace has no git repository.

### [cr_e5f6g7h8] src/extension.ts line 67 — OPEN
> The disposable returned here is never pushed to
> context.subscriptions. Memory leak on deactivation.

For each comment:
1. Fix the issue in the relevant file
2. In .code-review/reviews.json, set status to "addressed",
   add addressedAt timestamp, and append a thread reply
   with role "agent" explaining what you changed
3. Do NOT mark as "resolved" — that's for the human reviewer

reviews.json Field Reference

FieldTypeDescription
idstringStable cr_XXXXXXXX ID. Used by agent to find the right comment.
statusenumopen → addressed → resolved. Agent sets addressed; human sets resolved.
commitHashstringFull SHA of the commit being reviewed. Lets the extension show the right diff context.
filestringRepo-relative path. Used for navigation and diff lookup.
linenumberLine number in the after version of the diff (right side).
lineEndnumber|nullFor multi-line range comments. null for single-line.
side"left"|"right"Which side of the diff. Usually "right" (new code).
bodystringMarkdown-supported comment text.
threadReply[]Ordered list of replies. Agent appends here.
addressedAtISO date|nullWhen agent marked it addressed.
addressedByCommitstring|nullThe commit hash where the fix landed.
